# 손절선 계산기 · Stop-loss calculator

시나리오 표와 변동성을 넣으면 장기 성장률이 가장 높아지는 손절선을 계산하는 페이지다. 한국어는 `/`, 영어는 `/en/`.

A page that computes, for a scenario table and a volatility, the stop-loss that maximizes long-run growth. Korean at `/`, English at `/en/`.

## What it computes

Inputs: scenarios (probability and expected return each), a volatility, the period of the table, and optionally an entry price, a current price and the months since entry.

Outputs: the best fixed stop-loss, expected growth with and without it, the probability of the stop by scenario, a chart of growth against the position of the stop, and the scenario probabilities updated by the price path.

The formulas are those of the study note "When do stop-loss and take-profit rules maximize long-run growth? Part I" (https://snowkonn.github.io/study/stoploss-part1-rate.pdf). They assume that the return is earned as a rate, that a scenario lasts for the period of the table on average with an end that is not known in advance, that a sale is not undone and its proceeds wait in cash, and that the whole account is in the position. The page states these assumptions and what changes without them. It is a tool for one's own scenarios, not a forecast and not investment advice.

## Layout

```
src/stoploss.js          the calculation and the page script (the calculation is exported for Node)
src/style.css            styles
data/copy.json           all text of the pages, Korean and English
data/site.json           address of the site and outgoing links
data/vol_universe.json   asset classes offered as volatility presets, one Yahoo Finance ticker each
data/vol.json            volatility estimates (generated by tools/update_vol.py)
tools/update_vol.py      Yahoo Finance daily closes (yfinance) -> data/vol.json
build.py                 data + src -> docs/ (no third-party packages)
tests/check.js           the calculation against the numbers of the study note
docs/                    the built site (GitHub Pages serves this folder)
.github/workflows/       weekly refresh of the volatility table
```

## Commands

```bash
node tests/check.js                                     # calculation against the study note
python build.py                                         # rebuild docs/
pip install -r requirements.txt && python tools/update_vol.py && python build.py   # refresh volatilities
python -m http.server -d docs 8000                      # preview at http://localhost:8000
```

## Volatility presets

`tools/update_vol.py` takes daily closes from Yahoo Finance, computes the sample standard deviation of daily log returns over the last 252 and the last 756 observations, and annualizes with the number of observations per year measured from the dates. These are historical values, not forecasts. The table is built into the page, so the page makes no request after it has loaded. To offer another asset class, add a row to `data/vol_universe.json`.

The workflow `.github/workflows/update-vol.yml` refreshes the table every Saturday morning (Korean time) and commits the rebuilt site. It can also be started by hand from the Actions tab.

## Publishing

GitHub Pages: Settings → Pages → Deploy from a branch → `main`, folder `/docs`. `data/site.json` holds the address used in canonical links and the sitemap.
